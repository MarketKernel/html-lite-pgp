# Simple PGP

**[English](../README.md)**

OpenPGP для GnuPG и Kleopatra в **одном HTML-файле**, и **вся криптография — в этом
репозитории**: ни npm-пакетов, ни внешних библиотек, ни даже WebCrypto браузера. Программа
создаёт пары ключей, шифрует, подписывает, расшифровывает и проверяет текст и файлы; то, что
она пишет, читают GnuPG и Kleopatra, а она читает написанное ими. Работает без сети — файл
открывается прямо с диска, — и доступа к сети у страницы нет вовсе.

Это упрощённая сестра html-pgp: один вид ключа вместо двенадцати — тот, где реализации
труднее всего ошибиться. Обоснование, профиль формата и план — в [Task.md](../Task.md).

## Один алгоритм: Curve25519

Каждый ключ — **Ed25519 для подписи с подключом Cv25519 для шифрования**, как GnuPG 2.3+ и
Kleopatra делают по умолчанию, в формате OpenPGP v4, который читает любой GnuPG. Сообщения —
**AES-256 в CFB с MDC** (SEIPD v1), подписи — **SHA-512**.

Почему именно он, раз код свой:

- **Ключ — это 32 случайных байта.** Искать и проверять нечего; RSA нужны простые числа, и
  каждая проверка при генерации — место для ошибки.
- **Без длинной арифметики.** Поле Curve25519 считается 16 «конечностями» без ветвлений по
  секрету (по TweetNaCl); RSA в JavaScript — это BigInt, не постоянный по времени.
- **Детерминированная подпись.** У Ed25519 нет случайного nonce, повтор или утечка которого
  выдала бы ключ, в отличие от ECDSA и DSA.
- **X25519 принимает любые 32 байта** как открытый ключ: атак через чужую кривую нет; нулевой
  результат (точка малого порядка) отвергается.

Цена: **у получателей должны быть ключи Curve25519.** Пользователь GnuPG с ключом RSA может
добавить подключ: `gpg --quick-add-key <отпечаток> cv25519 encr`.

## Как пользоваться

Соберите `build/html-simple-pgp.html` (раздел «Сборка») и откройте в браузере.

- **Ключи** — создать пару, импорт (файлы, буфер обмена, вставленный текст, перетаскивание),
  экспорт, резервная копия, смена срока и пароля, отзыв, сертификат отзыва, **отметка
  «сверен»** после сверки отпечатка с владельцем (локальная неэкспортируемая сертификация, как
  `gpg --lsign-key`), удаление.
- **Блокнот** — зашифровать для получателей (и себя), подписать и зашифровать, подписать
  открытым текстом, расшифровать и проверить — на месте.
- **Файлы** — то же для файлов, отсоединённые подписи (`report.pdf.sig` находит `report.pdf`),
  файлы ключей.
- **Настройки** — язык (английский, русский), тема, сколько помнить пароли, откуда брать
  случайность, где хранить ключи.

### Откуда случайность

Новый ключ делается из **одного** источника, выбранного в окне создания; источники не
смешиваются:

| Источник | Как | Можно создать ключ заново? |
| --- | --- | --- |
| **Аппаратный генератор** | `crypto.getRandomValues` — генератор системы, питаемый аппаратным шумом; единственный его вызов в программе | нет |
| **Движения мыши** | движения указателя (только настоящие: созданные скриптом не считаются) и время нажатий клавиш, не больше бита за событие, 256 событий за не меньше чем 2 секунды | нет |
| **Парольная фраза** | scrypt (N=2¹⁸, r=8, 256 МиБ) от фразы и адреса почты; дата ключа — полночь UTC выбранного дня | **да**: фраза + адрес + дата, или фраза + открытый ключ |

Во фразе — не меньше пяти разных слов, на любом языке, предлоги считаются. **Открытый ключ
публичен, и любой может перебирать к нему фразы без ограничений.** Пять придуманных слов можно
подобрать; берите семь и больше случайных. Вывод ключа зафиксирован навсегда (версия 1,
`tests/vectors/phrase/v1.json`).

Каждому сообщению тоже нужны свежие случайные байты: от аппаратного генератора или — по
настройке — от мыши, раз за сеанс. Фраза для этого не используется. В любом случае байты идут
через HMAC_DRBG (SHA-512).

### Где хранятся ключи

- **В этом браузере** (IndexedDB), секретные ключи — под своими паролями.
- **В файле-контейнере**: вся связка в одном OpenPGP-сообщении, зашифрованном паролем (не
  меньше пяти разных слов или 16 символов). GnuPG его открывает:
  `gpg -d keys.gpg | gpg --import --import-options import-local-sigs`. В режиме контейнера
  ключи живут на странице, только пока она открыта; изменения пишутся обратно в файл — сами в
  Chrome и Edge, кнопкой «Сохранить» в остальных. Держите файл на флешке или в зашифрованном
  томе (VeraCrypt, BitLocker To Go, FileVault).

Чего страница **не может**: работать ключом внутри смарт-карты OpenPGP, YubiKey или Nitrokey
(WebUSB блокирует смарт-карты; Web Smart Card API — только для Isolated Web Apps), обращаться к
хранилищу ключей системы или TPM. Чтобы держать ключ на карте: сделайте копию, импортируйте её
в Kleopatra или GnuPG, перенесите командой `keytocard` и работайте с картой через GnuPG. Ключи
доступа (passkey) и аппаратные ключи работают только в устанавливаемом приложении — см. ниже.

### Устанавливаемое приложение (PWA) и ключи доступа

`build/pages/` — та же страница в виде устанавливаемого приложения, для любого https-хоста
(`.github/workflows/pages.yml` публикует её на GitHub Pages; домен задаётся в настройках
хостинга, в сборке его нет). Обновляется кнопкой в настройках, работает без сети и добавляет то,
что позволяет WebAuthn, — ему нужен https-адрес, поэтому в однофайловой версии этого нет:

- **Отпирать касанием** (меню ключа): ключ доступа (Touch ID, Face ID, Windows Hello, телефон)
  или аппаратный ключ (YubiKey и другие ключи FIDO2) отпирает ключ вместо пароля. PRF устройства
  (`hmac-secret`) даёт ключ, которым обёрнута вторая копия секрета (SEIPD v1, AES-256 + MDC) в
  браузере; копия под паролем остаётся.
- **Хранить на устройстве** (меню ключа): сам секрет записывается в `largeBlob` устройства,
  читается обратно и сверяется с открытым ключом; затем, после явного «Понимаю», копию в
  браузере можно удалить. В связке остаётся собственная отметка GnuPG «секрет в другом месте»
  (`gnu-dummy`, как пишет `gpg --export-secret-subkeys`), так что копия и контейнер по-прежнему
  импортируются в GnuPG. Потеряно или сброшено устройство — потерян ключ: держите резервную копию.
- **Открывать контейнер касанием** (настройки, в режиме контейнера): устройство оборачивает
  ключ, выведенный из пароля контейнера, — но не сам пароль.

Всё, что возвращает устройство, сверяется с открытым ключом, как после пароля. Эти функции
включены, только если программа **одна на своём origin**: в корне собственного (под)домена, не
на общем хостинге вроде `*.github.io`, где хранилище и ключи доступа origin делят другие проекты.
Иначе настройки объясняют, почему они выключены. Сам ключ доступа удаляется в настройках системы
(пароли и ключи доступа) или в программе аппаратного ключа — страница этого не умеет.

Поддержка зависит от браузера, системы и устройства и меняется. Браузерные тесты используют
виртуальные аутентификаторы Chrome (с PRF и large blobs и без них); **на реальных устройствах
ещё не проверено** — чек-лист:

| Устройство | Отпирать касанием (PRF) | Хранить на устройстве (largeBlob) |
| --- | --- | --- |
| Mac, Touch ID (Chrome, Safari) | ☐ | ☐ |
| Windows Hello (Chrome, Edge; Windows 11) | ☐ | ☐ |
| Android, менеджер паролей Google | ☐ | ☐ |
| iPhone, связка ключей iCloud | ☐ | ☐ |
| YubiKey 5 (прошивка ≥ 5.2 для PRF; large blobs — ?) | ☐ | ☐ |

Для каждого: подключить, запереть ключи («Забыть пароли»), подписать — пароль не спрашивается;
перезагрузить и подписать снова; для «хранить на устройстве» — удалить копию, очистить данные
сайта, импортировать контейнер или открытый ключ и отпереть, выбрав ключ доступа.

## Совместимость с GnuPG и Kleopatra

Проверено самим GnuPG (`tests/gnupg.test.ts`, во временном каталоге) и на том, что GnuPG
записал (`tests/fixtures/gnupg/`, один раз сделано `tools/gnupg-fixtures.sh`):

- GnuPG импортирует наши ключи с их предпочтениями (AES-256; SHA-512, SHA-256; без сжатия;
  MDC — и **без AEAD**, чтобы GnuPG 2.4+ отвечал в SEIPD v1, а не в OCB), открывает наши
  защищённые секретные ключи, видит смену срока и отзыв;
- GnuPG проверяет наши подписи открытым текстом и отсоединённые, расшифровывает наши сообщения
  (на ключ и по паролю) и проверяет подписи внутри;
- мы читаем ключи GnuPG (и секретные), его сообщения нам (на нескольких получателей, со скрытым
  получателем, сжатые, по паролю), подписанные тексты, отсоединённые подписи (и подписывающим
  подключом), сертификаты отзыва, контейнеры `gpg -c`.

То, что GnuPG шифрует в OCB (ключам, объявившим AEAD, — не нашим), и ключи других алгоритмов —
«не поддерживается».

Kleopatra работает через GnuPG; ручная проверка на Windows: импорт ключа отсюда (открытого и
копии), расшифровка сообщения и файла отсюда, проверка подписи отсюда, импорт контейнера после
`gpg -d`.

## Безопасность

- **Ничто не покидает страницу.** Политика CSP: `default-src 'none'`, `connect-src 'none'`,
  скрипт и стили разрешены **по их хэшам SHA-256**, а не `'unsafe-inline'`; Trusted Types не
  дают вставить HTML из строки. Всё встроено.
- **Никаких зависимостей.** В `package.json` их нет; импорты — только относительные или
  `node:`; криптография — в `src/core/crypto/`, `crypto.subtle` нет нигде
  (`tests/policy.test.ts`).
- **Постоянное время, насколько позволяет JavaScript**: AES в битслайс-форме (нет таблицы
  S-box, через которую ключ утекает по кэшу), арифметика кривой не ветвится по секрету.
- **Текст — только после проверки MDC**; изменённое или обрезанное сообщение не отдаёт ничего.
- **Key Overwriting** (2022): после каждой разблокировки открытый ключ вычисляется из секрета
  и должен совпасть; параметры KDF должны быть нашими.
- **Пароли не хранятся.** Разблокированные ключи живут в памяти столько минут, сколько задано.
  Контейнер держит в памяти на сеанс только ключ, выведенный из его пароля.
- Поля пароля — текстовые с нарисованными точками (из html-pgp), чтобы macOS Secure Input не
  включал латинскую раскладку.

Браузер — доверенная база: всё, что может выполнить код на странице или прочитать профиль
браузера, может прочитать то же, что и страница.

## Сборка

Node 24, ничего не устанавливается. Короче всего — `./build.sh`: собирает обе версии и печатает
SHA-256 файла; `./build.sh --check` заодно запускает тесты. То же по частям:

```sh
node --run build          # build/html-simple-pgp.html
node --run test           # unit-тесты (node:test, TypeScript исполняет сам Node)
node --run test:browser   # страница в headless Chrome (CHROME=/путь/к/chrome)
node --run check          # всё вместе
node --run bench          # скорость примитивов
```

Ни компилятора, ни сборщика из npm: типы снимает сам Node (`module.stripTypeScriptTypes`), модули
соединяет `build.mjs` — его правила в начале файла. Типы проверяет редактор (`tsconfig.json`), а
не CI: `tsc` — npm-пакет.

**Проверка выпуска**: сборка воспроизводима — один коммит даёт одни и те же байты. Сверьте файл с
`SHA256SUMS.txt` выпуска или соберите тег сами и сравните.

| Модуль | Откуда | Лицензия |
| --- | --- | --- |
| `sha1.ts`, `sha256.ts`, `sha512.ts`, `hmac.ts`, `pbkdf2.ts` | FIPS 180-4, RFC 2104, RFC 8018 | — |
| `scrypt.ts` | RFC 7914 | — |
| `drbg.ts` | NIST SP 800-90A (HMAC_DRBG) | — |
| `aes.ts` | FIPS 197; битслайс по `aes_ct` из BearSSL (Thomas Pornin) | MIT |
| `cfb.ts`, `keywrap.ts` | RFC 4880 §13.9, RFC 3394 | — |
| `field25519.ts`, `x25519.ts`, `ed25519.ts` | RFC 7748, RFC 8032; по TweetNaCl и tweetnacl-js | общественное достояние |
| `inflate.ts` | RFC 1951/1950; по `puff.c` Марка Адлера | zlib |

Проверено векторами стандартов, всеми векторами Wycheproof для Ed25519, X25519 и AES Key Wrap
(`tests/vectors/wycheproof/`, Apache 2.0) и сравнением с OpenSSL из Node на случайных данных.
Скорость (Node 24, Apple M): AES-256-CFB — 21 МиБ/с на шифровании, 38 МиБ/с на расшифровке;
SHA-512 — 90 МиБ/с; scrypt для ключа из фразы — 1,6 с.

Стили интерфейса и часть его кода — из html-pgp.

## Ограничения

- Только ключи Curve25519; только OpenPGP v4 (без v5/v6, без OCB).
- Файлы читаются в память целиком; предел — 256 МиБ.
- Без серверов ключей: обмен ключами — файлами или текстом.
- Кроме локальной отметки «сверен», чужие ключи не сертифицируются.
- Откуда взялся ключ (аппаратный генератор, мышь, фраза), помнит только браузер.
- Ключи доступа и аппаратные ключи: только в устанавливаемом приложении, на реальных
  устройствах ещё не проверены.
